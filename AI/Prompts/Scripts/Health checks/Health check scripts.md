# Health check scripts

Read-only jobs from phase 8 of the October 2026 plan (14 Oct 2026), kept so that the [[Monthly check-up]] and a full audit can measure the vault the same way again; since 21 Oct 2026 `health-report.js` runs the monthly check-up without an AI. Every script is a single `(async () => { … })()` expression for the vault's runner (`.work/plan/phase-3-tools/runner.js`: copy the file into `.work/queue/`, the runner writes `.work/out/<job>.result.txt` and the JSON named in the script's first lines, then moves the job to `.work/queue/done/`). None of them changes a note. Each writes its results under `.work/out/`. `health-counts.js` and `health-settings.js` put the run's date in their output names; the others write fixed names (the 14 Oct job numbers, such as `s83a-render3.json`), so rename the output or edit the path before a second run if you want to keep the earlier file.

| Script | What it measures | Output |
|---|---|---|
| `health-report.js` (21 Oct 2026) | The monthly check-up without an AI: counts and unresolved links; the catalog against the library files (every PDF and DjVu linked once, `files:` resolving, notes in review, scans); names, empty notes and strays; the calendar tables and today's study-plan row; the dashboards rendered (Home, Home (mobile), the Calendar, Habits.base, Catalog.base, today's note); sizes with the hidden folders and a remote-vault estimate; new writing with unlinked references, by pattern; plugins and property types. Writes one note, *Needs attention* (with the prompt to run for each item), *Worth knowing*, *Fine* and the numbers against the previous report (read from its frontmatter), and changes nothing else. Each check is guarded: one that fails is listed at the end and the rest still run | `AI/Health reports/Health report <date>.md` and `.work/out/health-report-<date>.json` |
| `health-counts.js` | Counts (files, notes, folders); unresolved links; links to missing headings or blocks; ambiguous names; missing embeds; the catalog (every library file linked once, `files:` resolving, converted index notes, `source_pdf` existing, property problems); names outside the ASCII rule; property case and type conflicts (the `type` values include `text`, the 44 primary texts); empty and title-only notes; orphan files and notes; sizes by extension and folder, with and without PDFs; the hidden folders; identical files; Guide and Welcome paths that do not resolve; plugins. Memory guard 300 MB below Obsidian's heap limit | `.work/out/health-<date>b.json` |
| `health-settings.js` | `.obsidian/types.json` against the property values in use, and Obsidian's own (inferred) type of every other property against its values: `pages` is inferred as a number, so the page ranges of the converted notes ("887–904") show a warning in the properties pane; calendar and study-plan coverage of today; each `Templates/Views` script parses and is used; template use; Templater, community plugins, `app.json`, Homepage, Folder notes, Omnisearch, Smart Connections' folder exclusions (`.smart-env/smart_env.json`), snippets, workspaces and Sync state (read from the settings files, nothing written); the Goudriaan, Excalidraw, Journal, Notes and Scholars folders | `.work/out/health-<date>c.json` |
| `render-check.js` | Opens each listed note or Base in an active reading-view tab, waits, and records Dataview and Bases error boxes, console errors and the first text; closes its tab. Background tabs are deferred by Obsidian, so the tab must be active. Edit the `names` list first | `.work/out/s83a-render3.json` |
| `link-sweep.js` | In the converted books and the 12–13 Oct texts: links placed after an escaped bracket (`\[[[…]]\]`, all fine on 14 Oct) and chapter-only links into chapters whose Hebrew and English numbering differ (decide per book: Wright, Levinson and McClellan use Hebrew numbering; a psalm's title is its verse 1) | `.work/out/s84a-sweep.json` |
| `verse-slip-scan.js` | The OCR slip classes inside the Dyczkowski callouts of the 5,845 Tantrāloka verse notes: footnote numbers read as "?", "~" for a dash, "&", digits glued to words, unbalanced quotes, parenthesised terms (for a diacritics check against Monier-Williams) | `.work/out/s84i-versescan.json` |
| `reference-evidence.js` | For every row of [[Bible references to decide later]] (sections 1–2): the line with its links removed, the reference as the [[Reference linker]] parses it, the already-linked head of a list, and the candidate verses with their text (Hebrew as printed, English converted, LXX, NRSVue, Douay-Rheims). Loads `b3core.js` and `versif-eng.json` from `AI/Prompts/Scripts/Reference linker/` | `.work/out/s85a2-decide-prep.json` |
| `guide-numbers.js` | The numbers the Guide and Welcome state: catalog notes by kind (Markdown copy, PDF only, print, text), sizes by kind, what a remote vault would carry with the 14 Oct Sync settings, note counts, whether the folders the Guide names exist | `.work/out/s86j-numbers.json` |
| `plain-audit.js` | A line-for-line port of an audit script another model wrote (sizes, largest files, empty and orphan notes, YAML keys, folders by count). Its "broken wikilinks" and "tags" sections are artifacts of its own parsing (it strips everything after a note name's last dot, and counts `#3207` as a tag); Obsidian's own figures come from `health-counts.js`. Its `pname` follows Windows pathlib, so a table link `[[X\|label]]` is read as X (fixed 14 Oct 2026; before that the port reported false orphans and unlinked files) | `.work/out/vault_audit_report.txt` and `.work/out/s84c-gemini-audit-lists.json` |
| `long-paths.js` (26 Oct 2026) | Every file whose full Windows path (`C:\Vaults\Obsidian Vault\` and the path inside the vault) is 240 characters or more, longest first, and how many are over 259, where Windows and the Git backup stop (house rule 7). Run it after renames, or when a Git commit fails with *Filename too long* | `.work/out/long-paths.json` |

The runner needs `.work/out/` and `.work/queue/done/` to exist; create them with `app.vault.adapter.mkdir` if a phase-end clean-up removed them. The runner line to paste after an Obsidian restart is in the [[House rules for AI work|house rules]] (*The job runner*) and in the project's progress doc (07).

**Rendering under Vertical Tabs (21 Oct 2026):** Vertical Tabs deduplicates tabs, so a fresh tab opened by `render-check.js` for a note that is already open somewhere renders nothing. Read such a note from the leaf that shows it (`app.workspace.getLeavesOfType('markdown')`, then `view.previewMode.containerEl`), and open a fresh tab only for the rest, as `health-report.js` does.
